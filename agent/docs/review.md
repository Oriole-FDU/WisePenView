# PR Review 规范

Review 的目标是确认行为、边界、回归风险和验证证据，不是要求 Codex 重写无关代码。

## Review 前

- 确认 PR 基线、当前 head、CI 状态和工作区状态。
- 先阅读 PR 描述，再按变更范围读取架构专题。
- 优先查看高风险文件：请求边界、mapper、service、registry、路由、权限、状态生命周期和基础交互组件。

## Review 评论分类

- **必须修复**：错误行为、回归、数据协议破坏、安全或类型问题。
- **建议修改**：可读性、局部结构、重复逻辑或缺少文档。
- **需要确认**：接口、权限、产品行为或运行环境不明确。
- **无关评论**：超出本 PR 范围，应记录但不要顺手扩大改动。

每条有效评论都要能对应到“评论 -> 文件/行 -> 修改 -> 验证”。

## 修复后

- 在原 PR 分支修改，不新开无关 PR。
- 不静默关闭有效讨论；回复中说明修改位置和验证结果。
- Review 修复可以使用独立 `fix(review): ...` commit，保持一个 commit 一个意图。
- 未经用户明确要求，不 force push、不发送 GitHub 评论、不合并 PR。
