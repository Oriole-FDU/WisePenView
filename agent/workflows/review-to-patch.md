# Review 到修复工作流

## 1. 读取 Review 上下文

确认 PR 的 base/head SHA、工作区、CI 状态和未解决评论。先看 PR 描述与整体 diff，再进入评论行号，避免只修复孤立句子。

## 2. 分类和确认

每条评论标记为“必须修复、建议修改、需要确认、无关评论”。涉及产品行为、接口契约、权限或大范围重构时先向用户确认。

## 3. 实施

在原 PR 分支修改，保持每个修复意图清晰。不要为满足评论而新增 wrapper、alias、重复实现或无关格式化。

## 4. 验证

使用 `agent/docs/verification.md` 选择检查。修复失败的 CI 时，必须重新覆盖原失败步骤；旧的绿色 CI 不能作为本轮验证证据。

## 5. 回复和交付

用 `agent/templates/review-response.md` 生成回复草稿，逐条说明：处理结论、文件/行、修改方式、验证命令和仍需人工确认的内容。未经用户明确要求，不发送评论、关闭线程或合并 PR。
